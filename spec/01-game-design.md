# 01. ゲームデザイン仕様

## 1. 基本ルール

- 盤面は **8x8 = 64 セル**。宝石は **6 種類**（`kind: 0..5`）。各種は色 + 固有の形状を持つ（[03-ui-ux.md](./03-ui-ux.md) の色覚多様性対応を参照）
- プレイヤーは **上下左右に隣接する** 2 つの宝石をスワップできる
- スワップの結果、同種の宝石が **縦または横に 3 個以上並ぶ**とマッチ成立、該当宝石が消える
- マッチが成立しないスワップは**無効**: 宝石は元の位置に戻る（戻りアニメーション + 小さな首振り）。ペナルティはない
- 消えた宝石の上にある宝石は**重力で落下**し、空いた最上部には新しい宝石が**盤外上方から降ってくる**
- 落下・補充の結果また 3 個以上並べば**連鎖（カスケード）**として自動で消える。安定するまで繰り返す
- **タイマーなし・手数制限なし・ゲームオーバーなし**。いつまでも遊べる

### 初期盤面

- 生成時点でマッチが 1 つも存在しないこと
- 有効手（マッチを作れるスワップ）が 1 つ以上存在すること

### 有効手がなくなった場合

- **無言で自動リシャッフル**する。モーダルもメッセージも出さない（Calm ピラー）
- 演出: 全宝石がふわっとフェードアウト（200ms）→ 配置し直し → フェードイン（300ms）
- リシャッフルは既存宝石の**構成（種類の内訳・特殊ピース）を保存**した並べ替えとし、「マッチなし + 有効手あり」を満たすまで再試行する（上限 50 回。超えたら新規盤面にフォールバック — 実質到達不能だが関数を全域にする）
- 統計 `gamesShuffled` に計上する

## 2. カスケードとコンボ

カスケードの 1 回の消去〜落下〜補充を **1 ステップ** と呼ぶ。

- スワップ直後の最初の消去が **ステップ 1（コンボ 1）**
- 落下・補充の結果による連鎖消去がステップ 2, 3, ... とコンボを加算する
- コンボは盤面が安定して操作可能（IDLE）に戻った時点でリセット
- 連鎖解決中はプレイヤー入力を受け付けない（先行入力キューも持たない — 落ち着いた操作感を優先）

## 3. スコア

```
ステップのスコア = (消えた宝石数 × 10) × コンボ数
```

- 式の単一情報源は `engine/scoring.ts` の `stepScore(clearedCount, combo)`（純関数・テスト対象）。ゲームループはこれを呼ぶだけで、式を再実装しない
- 特殊ピースの効果（ビーム・爆風・全消し）で消えた宝石も「消えた宝石数」に含む
- チェーン発火（後述）はすべて同一ステップ内の消去として合算する
- 累計スコアはセッション表示用の `score` と、生涯累計の `stats.totalScore`（永続化）の両方に加算する

### 例

3 連鎖で各ステップ 3 個・4 個・5 個消えた場合:

| ステップ | 消去数 | コンボ | スコア |
|---|---|---|---|
| 1 | 3 | ×1 | 30 |
| 2 | 4 | ×2 | 80 |
| 3 | 5 | ×3 | 150 |
| 合計 | | | **260** |

## 4. 特殊ピース

特殊ピースは 4 種類（laserH / laserV / bomb / prism）。すべて通常の宝石と同じ `kind` を持ち、発動モデルは共通:
**「マッチの一部として消される瞬間、または他の特殊ピースの効果に巻き込まれた瞬間に発動する」**。

| ピース | 生成条件 | 効果 |
|---|---|---|
| **laserH** / **laserV** | 横 / 縦の **直線 4 個** マッチ | 自分の行 / 列の全宝石を消す（ビーム掃引） |
| **bomb** | **L 字 / T 字**（同種の横グループと縦グループがセルを共有） | 自セル中心の **3x3** を消す（盤外はクリップ） |
| **prism** | **直線 5 個以上** のマッチ | 盤面上の **同 kind 全宝石** を消す |

### 4.1 生成ルール

| 条件 | 結果 |
|---|---|
| **横 4 個** の直線マッチ | その種の **laserH** が 1 個生成される |
| **縦 4 個** の直線マッチ | その種の **laserV** が 1 個生成される |
| **5 個以上** の直線マッチ | その種の **prism** が 1 個生成される |
| **L 字 / T 字**（同種の横・縦グループがセルを共有。3+3 に限らず 4+3 等も対象） | 共有セルに **bomb** が 1 個生成される（両グループを消費） |

- 1 つのマッチグループが生成するピースは最大 1 個
- 交差が成立した時点で bomb 生成がグループを消費するため、その 2 グループから laser / prism は生成されない。ただし直線 4 のグループが prism の条件（5+）と同時に満たされることはなく、判定順は **prism → bomb → laser**

### 4.2 生成位置（決定的・テスト可能）

1. **laser / prism**: プレイヤーが**スワップで動かしたセル**がマッチグループに含まれる場合 → そのセルに生成
2. **laser / prism**（カスケードで自然発生）: 横グループは**中央セル**（`cells[floor(len/2)]`）、縦グループは**最下段セル**に生成
3. **bomb**: 横・縦グループの**共有セル（角）** に生成。swapTarget に関係なく角固定（説明が最も簡単で決定的）
4. 同一セルが複数の生成条件を満たした場合はピース 1 個のみ、優先度 **prism > bomb > laserH > laserV**
5. 生成セルはそのステップの消去対象から**除外**する（生成したピースは消えずに盤面に残る）

### 4.3 発動ルール

- 発動条件は全種共通: スワップ / カスケードのマッチで消される瞬間、または他の特殊ピースの効果（ビーム・爆風・全消し）に巻き込まれた瞬間
- **laser**: 盤面を貫くビームを放ち、自分の行（laserH）/ 列（laserV）の全宝石を消す
- **bomb**: 自セル中心の 3x3（盤外クリップ）を消す。演出は爆発ではなく「ふわっと花が開く」bloom（Calm ピラー）
- **prism**: 盤面上の同 kind 全宝石を消す。全対象が同時にやわらかくフェード + 澄んだチャイム音
- **チェーン発火**: 効果で消された宝石の中に別の特殊ピースがあれば、それも即座に発動する。連鎖はすべて**同一ステップ内**で解決し（スコアも同一ステップに合算）、コンボはステップ単位でのみ加算する。各ピースは最大 1 回しか発火しないため必ず停止する
- 効果は行/列/範囲上の**すべての宝石**を消す。氷付き宝石は例外（[§7 参照](#7-盤面ギミック-氷) — 消える代わりに氷が 1 層減る）

### 4.4 特殊ピースが絡むスワップの有効性

| スワップ | 有効性 |
|---|---|
| 特殊ピースを動かしてマッチ成立 | 有効（発動） |
| 特殊ピースを動かしてもマッチ不成立 | **無効**（通常宝石と同じく戻る） |
| **特殊ピース同士**のスワップ（laser×laser / laser×bomb / bomb×prism / prism×prism 等すべての組合せ） | **常に有効**（マッチ不要の例外）。両方が交換後の位置から発動する。例: laser 同士なら行 + 列の十字消し、prism 同士なら 2 色同時全消し |

## 5. ジュース演出（コンボテキスト）

コンボテキストは Canvas ではなく **DOM オーバーレイ**として、そのステップのマッチ重心位置に表示する（[02-architecture.md](./02-architecture.md) の juice イベント参照）。

| コンボ（ステップ数） | テキスト | ティア | 付随演出 |
|---|---|---|---|
| 1 | （表示なし — 通常マッチは静かに） | — | パーティクルのみ |
| 2 | `Combo 2!` | small | — |
| 3 | `Combo 3!` | small | — |
| 4 | `FABULOUS!!` | medium | 弱い画面シェイク |
| 5 | `AMAZING!!` | medium | 画面シェイク |
| 6 以上 | `TRANSCENDENT!!` | large | 強い画面シェイク |

- ティアはオーバーレイのフォントサイズ・グロー色・シェイク量（trauma 加算値）を決める
- テキストはふわっと浮き上がりながらフェードアウト（float-up + fade、CSS アニメーション）
- `prefers-reduced-motion` / 設定オフ時はシェイクなし・テキストは単純フェードに縮退

### その他のフィードバック

| イベント | 演出 |
|---|---|
| マッチ消去 | 宝石が 1 → 1.15 → 0 に弾けるスケール + パーティクルバースト（6〜10 個/宝石） |
| レーザー発動 | 宝石色のビームが行/列を掃引（250ms）。掃引方向に宝石が順に消える（18ms/セル） |
| 無効スワップ | 戻りトゥイーン + 4px の水平「イヤイヤ」ウィグル |
| ハプティクス | マッチで 10ms、コンボティア上昇で 20ms の微振動（設定でオフ可・非対応端末は無視） |
| サウンド | 柔らかいシンセ音。コンボが上がるほど音程が上昇（設定でオフ可） |

## 6. 統計（stats）

Tabs の統計画面に表示し、localStorage に永続化する生涯累計値:

| キー | 内容 |
|---|---|
| `totalScore` | 生涯累計スコア |
| `bestCombo` | 最大コンボ数 |
| `gemsCleared` | 消した宝石の総数 |
| `lasersFired` | レーザー発動回数 |
| `bombsDetonated` | ボム発動回数 |
| `prismsFired` | プリズム発動回数 |
| `iceBroken` | 割った氷の層数 |
| `dailiesPlayed` | デイリーチャレンジを遊んだ日数（その日の初プレイで +1） |
| `gamesShuffled` | 自動リシャッフル発生回数 |

セッション限りの値: `score`（現在スコア）、`combo`（現在コンボ表示）。

## 7. 盤面ギミック: 氷

宝石を包む「霜」。**デイリーチャレンジの盤面にのみ登場する**（エンドレスは純粋な禅モードのまま — ランダムに出現する障害物は Calm ピラーに反するプレッシャー源になる）。デイリーの「今日の庭の景色」として日替わりの氷配置が出る、という位置づけ。

| 項目 | ルール |
|---|---|
| 表現 | `Gem.ice: number`（0 = なし、1〜2 = 層数）。独立したセル状態ではなく**宝石の属性**（Board 型・重力・マッチ検出を無変更で済ませる最小表現） |
| マッチ参加 | **する**（kind は見えているので普通にマッチに数えられる） |
| 消去時 | 消える代わりに **氷が 1 層減る**。0 層になった後に再度消されると普通に消える。ビーム・爆風・全消しも同一ルール（「消去 1 回 = 氷 1 層」の単一規則） |
| スワップ | 氷付き（ice > 0）の宝石は**動かせない**（無効スワップと同じ首振りで戻る。ペナルティなし） |
| 落下 | **通常どおり落ちる**（凍ったまま滑り落ちる） |
| 特殊生成 | 氷付き宝石には特殊ピースを生成しない（氷と special は併存させない） |
| 有効手判定 | 氷絡みのスワップは無効として判定。リシャッフルは氷ごと並べ替える |

停止性: マッチした全宝石が氷付きでも、そのステップで全員の氷が 1 層減り（宝石は残る）、同じマッチが再検出されて次のステップで消える。層数は有限なので必ず停止し、コンボが 1 つ余分に進むのはむしろ心地よい。

## 8. デイリーチャレンジ「Today's Garden」

「競う」を**過去の自分との比較 + 収集**だけで表現する。ランキング・タイマー・回数制限・失敗の概念は一切ない。

| 項目 | ルール |
|---|---|
| 盤面 | ローカル日付（`YYYY-MM-DD`）からシードを導出した**決定的盤面**（+ 氷 6 個配置）。同じ日は誰がいつ始めても同じ初期盤面・同じ補充ストリーム |
| 遊び方 | エンドレスと同一ルール。同じ日に**何度でも**遊べる |
| 目標 | スコア閾値 3 段階（**500 / 2,000 / 5,000**）で**花が灯る**（🌸 が 1〜3 個）。達成しなくても何も失わず、「未達成」の表示も出さない。3 輪灯った後も好きなだけ続けられる |
| 記録 | その日の**ベストスコアのみ**永続化（カスケード終端でベスト更新時に保存）。「セッション終了」の概念はなく、いつ離脱してもよい |
| ストリーク | **持たない**（「毎日やらなければ」は Calm に反する）。代わりに累計 `dailiesPlayed` を実績に使う |
| 履歴 | 過去の日の記録は保持しない（当日分のみ。日付が変われば上書き） |

決定性の意味: 開始盤面と補充ストリームが日付から一意に決まる。プレイヤーの手順が違えば展開は変わる — それでよい（同じ庭を各自が好きに手入れする）。シード導出は `seedFromString("daily:" + dateKey)` → mulberry32（[02-architecture.md](./02-architecture.md) 参照）。

## 9. 実績「Garden Goals」

stats を材料にした純関数判定（`stats → boolean`）の実績システム。解除は不可逆で、一部の実績は**テーマパックを解放**する（[03-ui-ux.md](./03-ui-ux.md) §5 参照）。隠し実績は作らない — 未解除でも条件をそのまま表示する（探索プレッシャーを避ける）。

| id | タイトル | 条件（stats） | テーマ解放 |
|---|---|---|---|
| `ripple` | Ripple | bestCombo ≥ 3 | — |
| `flow-state` | Flow State | bestCombo ≥ 6 | — |
| `gem-stream` | Gem Stream | gemsCleared ≥ 1,000 | — |
| `river-of-gems` | River of Gems | gemsCleared ≥ 10,000 | 候補 |
| `lightbender` | Lightbender | lasersFired ≥ 50 | — |
| `gentle-thunder` | Gentle Thunder | bombsDetonated ≥ 25 | — |
| `prismatic` | Prismatic | prismsFired ≥ 10 | **あり**（同梱の画像パック） |
| `calm-collector` | Calm Collector | totalScore ≥ 100,000 | 候補 |
| `thaw` | Thaw | iceBroken ≥ 100 | — |
| `seven-mornings` | Seven Mornings | dailiesPlayed ≥ 7 | 候補 |

- テーマ解放との連携契約は実績定義の `unlocksTheme?: string`（テーマパック id）**のみ**。テーマ側は解除済み実績リストを読んで解放判定する。それ以外の結合を作らない
- **割り当て方針**: 解放対象にできるのは同梱パックだけ。v2 時点の同梱は `pastel-bloom`（**常時解放** — テーマ機能の入口として最初から選べる）と画像パック 1 つ（`prismatic` で解放）。「候補」の実績は当面 `unlocksTheme` なしの通常実績として実装し、パックが増えたときに割り当てる
- 解放判定は**選択 UI のみ**で強制する（未解放パックは設定でロック表示・選択不可）。`settings.skin` に既に入っている値は解放状態に関わらず `resolveTheme` がそのまま解決する — 遊んでいるテーマを後から取り上げない
- 判定タイミングは stats が変化するステップ境界のみ（フレーム毎のコストなし）
- 通知は小さなグラスチップのトースト（[03-ui-ux.md](./03-ui-ux.md) 参照）。入力を遮らず、音・振動は既存の設定ゲートに従う
